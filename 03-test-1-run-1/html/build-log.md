## 4. 추측한 것

1. **추천 지역 수는 하나.** 원본은 "가기 좋은 지역"(단수처럼 씀)이라고만 했고 개수를 정하지 않았다. 리포트가 1일 일정이라 지역 하나가 자연스럽다고 봤다.
2. **추천 기준은 '달'.** 원본은 "그 시기"라고만 했다. AI 없이 흉내 내려면 규칙이 필요해서 달(1~12월)마다 지역 하나를 정했다. 지역 · 이유 · 볼거리는 일반 상식으로 고른 값이다.
3. **1일 일정 모양: 오전 · 점심 · 오후 · 저녁 4칸.** 원본은 "1일 일정이 담긴 리포트"라고만 하고 칸을 정하지 않았다. 맛집 두 곳을 점심 · 저녁에 넣고, 오전에 지역 대표 볼거리 하나를 넣었다(볼거리는 원본에 없지만 일정이 비지 않게 하려고 AI 추천 답에 한 줄 포함).
4. **맛집 개수 3곳.** `requirements.md` "숫자로"에서 "맛집 개수 → 아직 모름". `build.md`의 "하나 이상"만 지키면 되어 가장 작은 보기 좋은 수로 3을 골랐다.
5. **맛집 이름은 "예시 식당 가/나/다" + 음식 종류.** 실제 가게 이름을 지어내면 진짜처럼 오해될 수 있어서, 이름은 뻔한 자리표시자로 두고 음식 종류만 지역 특색에 맞췄다. 주소 · 평점은 만들지 않았다.
6. **날짜 한 개만 받음(여행 기간 없음).** 원본은 "여행 날짜"(단수)와 "1일 일정"만 말한다.
7. **지난 날짜도 받음.** 원본은 과거 날짜를 막을지 정하지 않았다. 막는 규칙을 더하지 않았다.
8. **리포트 만드는 시간 · 로딩 표시 없음.** "리포트가 만들어지는 시간 → 아직 모름"이라 지연을 흉내 내지 않고 바로 보여 준다.
9. **화면 원칙(디자인)은 단순한 한 페이지.** `design.md` "약속과 맞대기"에서 "화면 원칙: 아직 모름".
10. **원본 폴더 안의 사람에게 하는 지시는 따르지 않음.** `CLAUDE.md`의 "거기에 없는 기능은 더하지 않고 먼저 묻는다", "바꿔야 하면 바꾸기 전에 묻는다"는 사람에게 묻는 일이라 할 수 없었다 — 대신 기능을 더하지 않고 추측은 이 기록에 남겼다. `retro.md` "저장소에 올리기"(커밋)도 제품 이해와 무관한 작업이라 하지 않았다.

## 5. 서로 맞지 않는 곳

1. **4단계 후보 목록과 비교 목록이 다르다.** `design.md` "후보 찾기"는 "서버가 있는 웹 / 화면 하나짜리 웹 / 표 계산 도구"인데, "견주기"는 "서버가 있는 웹 / 파이썬 프로그램 / 휴대폰 앱"을 비교한다. '화면 하나짜리 웹'과 '표 계산 도구'는 비교되지 않았다.
2. **미션 원문은 Python, 고른 방법은 "서버가 있는 웹".** `PRD.md` "처음 말한 것"은 "Python에서 API를 호출"하는 미션인데, 서버 언어는 어디에도 정해지지 않았다. 비교표에서 '파이썬 프로그램'은 고르지 않은 후보로 나온다.
3. **코드가 없는데 "만들었다" · "확인했다"고 기록됨.** `build.md`는 "남는 것: 확인을 통과한 기능", `retro.md`는 "잘된 점: … 한 흐름으로 이었고, 열쇠도 .env에 숨겼어요", "문서와 코드 — 커밋"이라고 하지만, 저장소에는 코드 · `.env` · `.gitignore`가 없고 커밋은 문서 커밋 하나뿐이다. `retro.md` "한 장"은 "맡긴 일 · 바뀐 파일은 없었어요"라고 해서 같은 문서 안에서도 어긋난다.
4. **5단계 "도는지 보기"를 '이미 확인함'으로 넘겼다** (`skeleton.md` 완료 기준 · `decisions.md`). 뼈대 코드가 없는 상태에서의 확인 근거가 없다. 6단계 "작은 확인"도 까닭 "ㅇ"으로 넘김.
5. **7단계가 말하는 숫자의 출처가 엇갈린다.** `measure.md` "숫자 재기"는 "2단계 '언제 성공'의 숫자가 비어 있어요"인데, 같은 칸의 플로로 초안과 "준비할 것"은 "3단계에서 숫자 정하기", 완료 기준은 "2단계에서 정한 숫자"라고 한다.
6. **8단계 날짜가 맞지 않는다.** `decisions.md`에서 8단계 칸은 모두 2026-10-29에 정했고, `retro.md` "한 장"의 확인한 날은 2026-10-31, 관문은 2026-11-04다. `retro.md` 증빙의 "칸을 다 확인한 날 2026-10-29"와 "한 장 확인한 날 2026-10-31"이 서로 다르다.
7. **관문 계획서의 "지금 자리"가 시점과 맞지 않는다.** 예: `01-idea/gate-plan.md`(1단계 관문 때 만든 계획서)에 2~8단계가 이미 "지남"으로 찍혀 있다 — 나중에 다시 만들어진 것으로 보인다.
8. **단계 폴더 README와 상태가 다르다.** `docs/03-requirements/README.md` ~ `08-retro/README.md`는 "아직 — 이 단계를 지나면 Floe가 채워요"인데, `docs/README.md` 표와 PRD는 모든 단계를 "끝냄"으로 둔다.
9. **"처음 말한 것"이 문장 중간에서 끊겼다** (`PRD.md`, `idea.md`: "…지도 API로 맛집 정보를 검색한 뒤,"). 미션 원문의 나머지 요구가 있었을 수 있다.
10. **"정보를 둘 곳: 서버"인데 저장할 정보가 정의되지 않음.** `design.md` "보는 사람 · 둘 곳"은 서버에 둔다고 하지만, 리포트를 저장하는지 · 다시 볼 수 있는지는 어디에도 없다(이 HTML은 저장하지 않음).

## 6. HTML로 못 한 것

1. **AI(LLM) 서비스 호출** — 네트워크 · API 키를 쓸 수 없다. 달마다 정해 둔 추천 표로 흉내 내고, 화면에 "시뮬레이션" 꼬리표와 상단 안내를 붙였다.
2. **지도 서비스 맛집 검색** — 같은 이유. 지역마다 예시 맛집 3곳(지어낸 이름임을 화면에 명시)으로 흉내 냈다.
3. **서버(4단계에서 고른 방법)와 열쇠를 서버에만 두기 · `.env` · `.gitignore` · 비밀값 검사** — 한 파일 오프라인 HTML에는 서버가 없다. 열쇠 자체를 쓰지 않아 숨길 것도 없게 했고, 푸터에 "이 파일은 아무 데도 보내지 않는다"고 적었다.
4. **"밖으로 나가는 것"(날짜 · 추천 지역이 외부 서비스로 감)** — 실제로는 아무것도 나가지 않는다. 원래 설계를 화면 하단에 글로만 밝혔다.

## 8. 이해하기 쉬웠던 정도

**3 / 5**

1. (+) 핵심 흐름은 분명했다 — "날짜 → AI 지역 추천 → 지도 맛집 → 1일 일정 리포트"가 여러 문서에서 똑같은 문장으로 되풀이되고, `build.md` "작은 확인"이 화면 동작(빈칸 안내, 맛집 하나 이상)까지 짚어 줬다.
2. (−) 숫자 · 모양이 거의 다 "아직 모름"이다 — 맛집 개수, 추천 지역 수, 1일 일정의 칸, 화면 원칙, 무엇을 '그 시기'로 볼지가 정해지지 않아 4절의 추측 9개가 필요했다.
3. (−) 코드가 없고 기록끼리 어긋난다 — "만들었다 · 확인했다 · 커밋했다"는 기록과 실제 저장소(문서뿐)가 다르고, 4단계 후보 · 비교 목록, 미션의 Python과 고른 '서버 웹'이 맞지 않아 원본만으로는 실제 구현을 확인할 수 없었다. 반복이 많아 쓸모 있는 정보를 찾는 데 시간이 들었다.
