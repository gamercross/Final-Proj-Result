## 처음 말한 것

> 1. 미션 소개 Python에서 API를 호출한다는 게 처음엔 막막하게 느껴집니다. 그런데 한 번 연결되는 순간, 가능성이 달라집니다.  LLM API가 추천을 하고, 지도 API가 위치를 찾고, 최종 리포트가 생성되는 흐름 — 이걸 손으로 조합합니다.  단일 API 호출이 아니라 여러 API를 엮어 인사이트를 만드는 과정, 그게 이번 미션입니다.  현대 서비스의 대부분은 API를 통해 데이터를 주고받습니다. AI 기능, 지도 데이터 등 다양한 서비스를 API로 손쉽게 연동할 수 있습니다.  이 미션에서는 LLM API와 지도 API를 조합하여 국내 여행 추천 프로그램을 개발합니다. 사용자가 여행 날짜를 입력하면, LLM이 해당 시기에 여행하기 좋은 지역을 추천하고, 지도 API로 맛집 정보를 검색한 뒤,
>
> 통째로: [00-source/idea.md](00-source/idea.md) 1 ~ 225줄

## 1. 문제와 목표 — 1단계

- **불편** — 여행 날짜에 어디가 좋은지, 어디서 먹을지 하나하나 찾기 어려워요.
- **달라지는 것** — 날짜만 넣으면 추천 지역과 맛집이 담긴 여행 리포트가 만들어져요.
- **누가** — 여행 날짜를 넣고 여행 추천을 받는 사용자예요.
- **크기** — 크기: 보통 — AI와 지도를 차례로 부르는 흔한 방법으로 풀려요.

## 2. 아이디어와 범위 — 2단계

- **빈칸 채우기** — 누구: 여행 날짜를 넣는 사용자 · 불편: 어디가 좋은지, 어디서 먹을지 하나하나 찾기 어려워요 · 해결: 날짜만 넣으면 추천 지역과 맛집 리포트 · 어디까지: 추천, 맛집…
- **왜 · 어디까지 · 언제 성공** — 왜: 여행지와 맛집을 하나하나 찾기 힘들어서 · 어디까지: 지역 추천, 맛집 검색, 리포트(예약과 길찾기는 이번에 안 해요) · 언제 성공: 아직 모름
- **한 문장 한 가지** — 여행 날짜를 넣으면, 앱은 좋은 지역을 추천한다 / 지역이 정해지면, 앱은 그 지역의 맛집을 찾는다 / 결과가 모이면, 앱은 여행 리포트를 만든다
- **남의 정보 · 밖으로** — 남의 정보: 없음(여행 날짜만 받아요) · 밖으로 나가는 것: 여행 날짜는 AI에게, 지역 이름은 지도 서비스에게 가요

## 3. 꼭 필요한 기능 — 3단계

- **기능 문장** — 여행 날짜를 넣으면, 앱은 좋은 지역을 추천한다 / 지역이 정해지면, 앱은 그 지역의 맛집을 찾는다 / 결과가 모이면, 앱은 여행 리포트를 만든다
- **숫자로** — 좋은 지역 → 아직 모름 / 맛집 → 아직 모름 / 결과가 모이면 → 아직 모름
- **꼭 · 있으면 좋음** — 지역 추천: 꼭 / 맛집 찾기: 꼭 / 여행 리포트: 꼭
- **나온 곳 잇기** — 기능이 3개라 아직 안 해도 돼요
- **막을 일** — 여행 날짜 말고 다른 정보가 들어오면, 앱은 그 정보를 AI나 지도 서비스에 보내지 않는다

## 4. 만드는 방법 — 4단계

- **후보 찾기** — 서버가 있는 웹 / 화면 하나짜리 웹 / 휴대폰 앱
- **견주기** — 서버 웹: 열쇠 숨김 · 손이 많이 가요 / 한 화면 웹: 쉬움 · 열쇠 노출 / 휴대폰 앱: 편함 · 준비 길어요
- **고른 까닭** — 고른 방법: 서버가 있는 웹 — 까닭: AI와 지도를 차례로 부르고, 다른 정보가 나가는 걸 서버에서 막을 수 있어요
- **약속과 맞대기** — Python 쓰기: 맞음 — 서버에서 쓸 수 있어요 / 다른 정보 안 보내기: 맞음 — 서버에서 걸러요 / 화면 원칙: 아직 모름
- **보는 사람 · 둘 곳** — 누가 무엇을 보나: 사용자가 자기 리포트 · 정보를 둘 곳: 서버 · 들어올 때 확인: 불필요

## 5. 뼈대와 할 일 — 5단계

- **끝까지 잇기** — ① 여행 날짜 넣기 → ② AI가 좋은 지역 추천 → ③ 지도로 맛집 찾기 → ④ 여행 리포트 보여 주기
- **도는지 보기** — 날짜를 넣어 보면 → 추천 지역과 맛집이 담긴 리포트가 화면에 나오면 된다
- **작게 나누기** — 날짜 입력칸 만들기 / AI에게 지역 묻기 / 지도로 맛집 찾기 / 리포트 화면 만들기 / 다른 정보 막기
- **비밀값 검사** — AI와 지도 열쇠는 .env 파일에만 두고 올리지 않으며, 올리기 전에 검사해요.

## 6. 만든 것과 확인 — 6단계

- **확인 먼저** — 지역 추천 — 날짜를 넣으면 지역 이름이 나와야 해요 / 맛집 찾기 — 지역을 넣으면 맛집 목록이 나와야 해요 / 리포트 — 결과를 넣으면 한 장이 나와야 해요
- **작은 확인** — 날짜 입력칸이 값을 받아요 / AI가 지역을 돌려줘요 / 지도가 맛집을 돌려줘요 / 리포트가 화면에 떠요
- **써 보기** — ① 여행 날짜 넣기 → ② 추천 지역 보기 → ③ 맛집 확인하기 → 결과: 지역과 맛집이 담긴 여행 리포트가 나와요
- **비밀값 검사** — AI와 지도 열쇠는 .env 파일에만 두고 올리지 않으며, 올리기 전에 검사해요.

## 7. 잰 결과 — 7단계

- **숫자 재기** — 지역 추천: 날짜 넣고 지역 이름 나오나 / 맛집 찾기: 지역 넣고 목록 나오나 / 리포트: 한 장 나오나
- **잰 값 적기** — 무엇: (재고 적기) · 잰 날: (재고 적기)
- **못 잰 것** — 실제 키로 돌리기 — 아직 못 함(만든 프로그램을 실제 열쇠로는 아직 안 돌렸어요)
- **아무나 못 들어오게** — 공개하지 않아요 — 이 컴퓨터에서만

## 8. 배운 것 — 8단계

- **돌아보기** — 잘된 점: 시험 27개가 통과했어요 · 아쉬운 점: 실제 열쇠로는 아직 안 돌려 봤어요.
- **왜 다섯 번** — 왜? 실제로 안 돌려 봤나 → 열쇠가 없었나 → 먼저 가짜로 시험했나 → 진짜 확인을 뒤로 미뤘나 → 확인할 날을 안 정했어요.
- **아찔했던 일** — 없었어요 — 다음엔 여행 날짜 말고 다른 정보가 AI나 지도에 가지 않는지 먼저 시험할게요.
- **배운 것 남기기** — 다음엔 성공 숫자를 먼저 정해요 / 다음엔 실제 열쇠로 한 번 돌려 봐요 / 다음엔 열쇠를 올리기 전에 검사해요.
- **저장소에 올리기** — travel_planner.py와 시험 파일, 문서 — 커밋: 여행 리포트 첫 판 완성 (열쇠와 .env는 올리지 않아요)
