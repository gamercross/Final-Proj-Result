## 2. 이번 단계에서 한 일

- 가장 단순한 흐름을 처음부터 끝까지 이어 보기 — ① 여행 날짜 넣기 → ② AI가 좋은 지역 추천 → ③ 지도로 맛집 찾기 → ④ 여행 리포트 보여 주기
- 이어진 게 실제로 도는지 확인하기 — 날짜를 넣어 보면 → 추천 지역과 맛집이 담긴 리포트가 화면에 나오면 된다
- 남은 일을 작은 할 일로 나누기 — 날짜 입력칸 만들기 / AI에게 지역 묻기 / 지도로 맛집 찾기 / 리포트 화면 만들기 / 다른 정보 막기
- 비밀번호·키 같은 비밀값이 코드와 기록에 남지 않았는지 확인하기 — AI와 지도 열쇠는 .env 파일에만 두고 올리지 않으며, 올리기 전에 검사해요.

## 5. 공부할 말

- TDD — 확인 방법을 먼저 정하고, 그 확인을 통과하게 만드는 순서예요
- 단위 테스트 — 작은 부분 하나가 제대로 도는지 따로 확인하는 것이에요
- 수용 테스트 — 쓰는 사람 입장에서 처음부터 끝까지 써 보며 확인하는 것이에요
- 보안 점검 — 비밀값 검사 — 비밀번호나 열쇠 같은 값이 코드나 기록에 남지 않았는지 찾아보는 일이에요
- Walking Skeleton — 꾸미기 전에 처음부터 끝까지 이어지기만 하는 가장 단순한 모양이에요
- 스모크 테스트 — 켜 보고 바로 멈추거나 깨지지 않는지 먼저 보는 짧은 확인이에요
- 작업 분해 — 큰 일을 하나씩 끝낼 수 있는 작은 일로 나누는 것이에요
